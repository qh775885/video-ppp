# AI Development Rules

## 1. 提交规范 (Commit Guidelines)
- **中文优先**: Git 提交信息（Commit Messages）请尽量采用中文（简体）。描述要清晰、直达要害，准确说明该次提交修改了哪些功能或修复了什么 Bug。

## 2. 版本号控制 (Version Control)
- **智能更新**: 赋予 AI 自由控制、递增版本号的权限。每次完成重要功能或缺陷修复时，应当根据 SemVer（语义化版本）规范主动、合理地在 `package.json` 等配置文件中更新版本号。

## 3. 文档与说明 (Documentation Alignment)
- **主动维护**: AI 需要时刻关注并主动维护相关文档（如 `README.md`, `CHANGELOG.md`, `说明.md` 等）。
- **同步更新**: 在代码库发生变更或版本号更新时，自动补充修改点进入更新日志与项目说明中，保持文档与实际代码始终同步。

## 4. 迭代计划 (Iteration & Planning)
- **注重实操**: 维护和梳理项目的后续迭代计划时，必须基于“**实际可实施、可落地**”的原则。不堆列虚无缥缈的基础建设或未经验证的庞杂需求。
- **自动跟进**: 在修复旧问题或增加新功能后，主动划掉计划列表中已完成的条目，并智能推演出合理且切实可行的下一步开发建议。

## 5. 整体主导权 (Overall AI Autonomy)
- 遇到上述工作流相关的繁琐细节任务时，AI 需做到“**无需人工反复提醒，全自动、智能、闭环维护**”。每次提交修改后，自检这套流程是否已经妥善执行。
