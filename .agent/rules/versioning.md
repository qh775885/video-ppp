# 版本号与发布规范

## 版本号控制
- 遵循 SemVer，版本号只在 `package.json` 中维护
- UI 版本号从 `package.json` 动态导入（`Sidebar.jsx`），**禁止任何地方硬编码版本号**
- 递增时机：**用户确认问题已修复 / 功能已实现** 后才递增，AI 不得提前递增

## 发布流程
1. 用户确认功能稳定
2. 递增 `package.json` 版本号
3. 更新 `CHANGELOG.md`（顶部追加新版本条目）
4. 提交 + 推送
5. 用户从 `CHANGELOG.md` 复制文本到 GitHub Releases 发布

## CHANGELOG 写作规范 ⚠️ 关键
- 格式：`## vX.X.X` + 简洁条目列表
- **只写实际已实现且用户确认有效的改动**，不写未验证的内容
- 描述要简短直白，能直接复制粘贴到 GitHub Releases
- 不用 emoji 分类标题（如 ✨🐛），直接用 `-` 列表
- 不写花哨形容词，不写技术实现细节
- 不写内部开发改动（如代码重构、规则维护、版本号机制等），只写用户可感知的变更
- 跳过的/无实际变更的版本号不要出现在 CHANGELOG 中
